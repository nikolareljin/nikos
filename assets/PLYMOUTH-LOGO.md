# Plymouth Boot Splash

Plymouth draws on a bare framebuffer before any icon theme, font config or
toolkit exists, so every element of the splash has to be a pre-rendered PNG
sitting in the theme directory. The playbook copies them there as they are: no
rendering tool is needed on the target machine.

## Files

### Logo source

| File | Purpose |
|---|---|
| `plymouth-logo-source.svg` | Inkscape-editable source, open this to make design changes |
| `plymouth-logo.svg` | Optimized production SVG, minimal, no Inkscape metadata |
| `plymouth-logo.png` | Colour export, kept for reference and for any non-boot use |

### Boot chrome, in `plymouth/`

Generated by `scripts/render-plymouth-assets.py` and committed.

| File | Size | Drawn from | Used for |
|---|---|---|---|
| `logo-mono.svg`, `logo-mono.png` | 512x466 | `plymouth-logo.svg` | the mark and wordmark |
| `spinner-0001.png` ... `spinner-0036.png` | 96x96 | `menu-icon.svg` | activity, a highlight running along the "N" |
| `progress-meter.png` | 320x6 | drawn | boot progress track |
| `progress-fade.png` | 320x6 | drawn | boot progress fill, scaled horizontally |
| `fsck-meter.png` | 160x6 | drawn | disk check track |
| `fsck-fade.png` | 160x6 | drawn | disk check fill |
| `passw-dialog.png` | 300x36 | drawn | passphrase entry box |
| `bullet.png` | 14x14 | `menu-icon.svg` | one passphrase character |

Larger elements come from `plymouth-logo.svg`; the small ones come from
`menu-icon.svg`, which is the cut of the mark drawn to stay readable at icon
sizes.

All of it is greyscale on a transparent background. The boot background is set
in `nikos.script`, so anything opaque would show as a rectangle around the
element, and the mark's blue reads as a colour cast on a dim framebuffer.

## Updating the logo

### 1. Edit the design

Open `plymouth-logo-source.svg` in Inkscape and make your changes.

### 2. Sync the optimized SVG

Export a clean version without Inkscape metadata:

```
inkscape plymouth-logo-source.svg --export-plain-svg=plymouth-logo.svg
```

Keep `<svg>` as the first element after the XML declaration. gdk-pixbuf
identifies an SVG by sniffing the head of the file for `<svg>`, and a comment
ahead of the root element pushes it out of that window, which makes the file
undecodable to everything that loads it through gdk-pixbuf. `tests/test_assets.py`
enforces this.

### 3. Re-export the colour PNG

```
inkscape plymouth-logo.svg \
  --export-filename=plymouth-logo.png \
  --export-width=512 --export-height=466
```

### 4. Re-render the boot chrome

```
python3 scripts/render-plymouth-assets.py
```

This reads `plymouth-logo.svg` and `menu-icon.svg` and rewrites everything in
`plymouth/`. It needs PyGObject and the librsvg pixbuf loader
(`gir1.2-rsvg-2.0`, `librsvg2-common`), which are development dependencies
only.

Commit the sources and everything the script wrote.

## Testing the splash

There is no way to preview it locally: `plymouthd` takes exclusive control of
the framebuffer, and Ubuntu ships no X11 renderer for it. `tests/test_plymouth_theme.py`
covers what can be checked without booting, which is that the script registers
every handler it needs, that every image it loads exists, that the spinner
sequence has no gaps, and that the artwork is transparent and desaturated.

Anything beyond that needs a reboot or a VM.
